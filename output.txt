2. ROOT CAUSE ANALYSIS — `request is not a function` & MODULE LOADING FAILURES
--------------------------------------------------------------------------------
Investigation revealed that the failures stemmed from three interconnected architectural gaps:

2.1 Root Cause 1: Missing Prop Propagation & Lack of Defensive Fallback:
- In `ResearchWorkspaceView.jsx`, `request` was passed to certain tabs but omitted for:
  * `<CropCatalogView />` (causing `undefined.apply()` on catalog mount -> "request is not a function" -> 0 SPECIES).
  * `<CropFailureRecoveryView />` (causing "request is not a function" upon invoking shock simulation).
- Neither view imported `request as defaultRequest` from `./apiClient.js` as a fallback.
- Fix: Added dual-layer resilience:
  1) `ResearchWorkspaceView.jsx` now explicitly passes `request={request}` and `formatNumber={formatNumber}` to all views.
  2) All views now import `defaultRequest` and use `const request = typeof propRequest === 'function' ? propRequest : defaultRequest;`.

2.2 Root Cause 2: Circular Dependency & Unsanitized field_id in Sensitivity Analysis:
- In `SensitivityAnalysisView.jsx`:
  * Imported `formatNumber` from `./main.jsx`, causing a circular module dependency that could corrupt module scope evaluation.
  * Did not destructure `request: propRequest` from props, ignoring parent injection.
  * Passed unauthenticated string field IDs (e.g. `'SYN-BOG-01'`) directly to `/api/scenarios/sensitivity`, which caused `fid = int(requested_field_id)` in backend to crash with ValueError (HTTP 500) or HTTP 401 unauthorized for guest users.
- Fix:
  1) Imported `formatNumber as defaultFormatNumber` from `./marketUtils.js`.
  2) Sanitized `field_id` to only pass numeric IDs when valid, defaulting to `'demo'` for guest/synthetic sessions.
  3) Added a working retry button in error state and guaranteed `finally { setLoading(false); }`.

2.3 Root Cause 3: Dynamic Import Chunk Stall in Three.js Farm Simulator:
- In `ResearchWorkspaceView.jsx`, `ExperimentSimulator3DView` was loaded via `React.lazy()` with `<Suspense>` but without a local `ErrorBoundary`.
- If dynamic chunk loading stalled or WebGL context had issues, `<Suspense>` remained frozen on its loading screen indefinitely.
- Fix:
  1) Imported `ExperimentSimulator3DView` directly as an immediate component.
  2) Added `export default ExperimentSimulator3DView;` to ensure compatibility.
  3) Implemented `WorkspaceErrorBoundary` to catch any 3D rendering context issues and provide an instant "Reload Module" button and 2D fallback.

2.4 Root Cause 4: Missing Default Export in `apiClient.js`:
- `apiClient.js` only had named `export async function request(...)`. If any module used default import syntax, `request` evaluated to `undefined`.
- Fix: Added `export default request;` alongside named exports.
